# LearningUnity

>小的时候看流言终结者，探索频道。\
>广告时间经常出场一位做机器人的女性学者，说“证明你真的搞懂了最好的方法，就把它做出来一遍。”


1. 事事有回应
2. 当代码的搬运工前一定要把代码的作用搞搞清楚
3. 一定要写log，比起相信终将逝去的记忆，相信0和1的痕迹\
3.5. 烂代码比起写很多注释，不如把代码写写好。代码本身是self explanatory的，不应该需要再度解释
4. debug宛如做手术，下手前理清楚病因再开刀，不要瞎几把乱试\
4.5 代码自有它的道理，有问题一定是有这样的代码在作祟，再找找，信我
5. 不能为了灵活方便就忽视结构和复杂度管理。比如 public，goto 等
6. 每个方法都只应该做一件事
